## Правила работы (обязательно)

1. **Данные смотреть ТОЛЬКО через TablePlus или Supabase SQL Editor** — никогда не через curl/терминал
2. **JS/Python правки через `/tmp/`** — `cat > /tmp/fix.py << 'PYEOF'` → `python3 /tmp/fix.py`
3. **zsh ломает grep со скобками и heredoc со спецсимволами** — использовать python3
4. **Перед каждым изменением — SELECT** чтобы видеть текущее состояние
5. **Один шаг за раз** — один SQL → проверка → следующий
6. **Деплой только после локальной проверки** на `localhost:8000/v3/`
7. **Не трогать DR1 таблицы** (bank_transactions, personal_transactions, transactions, records)
8. **`balance` в payroll не редактировать вручную** — только через `total_accrued` и `total_paid` (триггер)

## Бизнес-логика (критичные нюансы)

### Выручка и данные
- Выручка мастера → только из `transactions`, **не** из `records.service_cost`
- `service_cost = 0` в records ≠ отсутствие выручки (оплата абонементом/сертификатом)
- Абонементы для мастера = прайс × 0.7 (скидка 30% клиенту, мастер проводит полный сеанс)
- Выручка абонемента в P&L: в день продажи. Для мастера: в день использования
- Fitmost выручка = по периоду визита (платёж приходит следующим месяцем)
- Fitmost записи: оригинал с `attendance=0` + дубль администратора с `attendance=1, is_fitmost=TRUE`
- Аренда Гилтон = 93 000 руб/мес, платёж 25-го за следующий месяц → использовать поле `period`
- ФОТ в P&L = метод начисления из `payroll.total_accrued` (не кассовый, не из `personal_transactions`)

### Тарифная сетка выходов под запись
| Длительность | Оплата |
|---|---|
| < 6300 сек (105 мин) | 1 500 ₽ |
| 6300–8400 сек (105–140 мин) | 2 000 ₽ |
| 8400–10800 сек (140–180 мин) | 3 000 ₽ |
| > 10800 сек (180+ мин) | 3 500 ₽ |

> Граница 6300 (не 6000): "Экспресс" 100 мин = 6000 сек → 1500₽ (нижняя граница включена)

### Парные программы
- Фильтр: `service_cost < price_min × 0.5` → второй клиент не пришёл
- Исключение: оплата сертификатом может давать 50% при полной явке → проверять вручную
- `attendance = -1` = отмена → исключать из парных программ (`.neq("attendance", -1)`)
- Два выхода в один день: `04.03=3500` в payroll = две записи в visit_records (1500+2000) → проверять по сумме, не по количеству

### Сотрудники
- Мария = "Александра К." в банковских переводах (через `staff_payment_aliases`)
- Мария — нет смен, только выходы под запись
- `records.staff_name` не всегда достоверен в выходные — администратор может записать на одного мастера хотя работали двое
- Payroll period: 1–14 и 15–31. Выплата 1-го числа = за предыдущий период (не текущий)
- Долг мастера (аванс > начислено) → переходит в следующий период через `offset_amount`

### Валидация данных
- 29 февраля в 2026 году не существует — парсер notes должен валидировать даты
- Суббота/воскресенье — данные `records.staff_name` могут быть недостоверны
- `is_double_shift` в shifts может быть проставлен некорректно — не доверять флагу слепо
- `company_id = null` при INSERT в shifts без явного указания → записи не попадают в API

## Anti-patterns (полный список из всех сессий)

| Запрещено | Почему / Правильно |
|---|---|
| `records.service_cost` как выручка | Только `transactions` |
| `bootstrap.Modal` | Использовать нативный Tabler |
| `dataPointSelection` в ApexCharts | Использовать `markerClick` или кликабельные строки таблицы |
| `?t=` cache-bust параметры | FastAPI не принимает лишние query params — падают молча |
| `balance` вручную | Только триггер через `total_accrued`/`total_paid` |
| `DELETE + INSERT` в импорте | Использовать `upsert` с `on_conflict` |
| `grep` со скобками в zsh | Использовать python3 |
| Инлайн JS в `index.html` | Весь JS только в `js/*.js` модулях |
| `window.*` флаги | Только `let` в `router.js` |
| `const/let` после использования | `visitRecordSum2` → "Cannot access uninitialized variable" |
| CSS правки без диагноза | Сначала `parentElement.className` + читать файл целиком — никаких гипотез до постановки диагноза |
| `disabled` option первым в select | Браузер не триггерит `onchange` при первом выборе |
| Supabase без пагинации | По умолчанию обрезает на 1000 строк — использовать `fetch_all()` |
| `is_visit_only` в проверках без фильтра | Ложные ошибки "мастер в расписании" |
